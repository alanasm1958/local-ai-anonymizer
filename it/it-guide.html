Local AI Anonymizer: IT install guide

Version {{VERSION}} · Chrome and Edge (version 128 or later) · Windows and macOS · Developed by Alan Al-Jammoor

What it is

A browser extension that replaces personal data (names, organizations, places, emails, phone numbers, IDs, card numbers, IBANs, keys) with placeholders such as [PERSON_1] before text or files reach AI chat sites. Detection runs inside the browser with a bundled model. Real values are kept in browser session memory and erased when the browser closes.

Security and data facts

  • No outbound network traffic. The model loads from the extension's own files (remote model loading is switched off in code). There is no telemetry, analytics or account.
  • No remote code. Manifest V3; all code ships in the package.
  • No model downloads. Only the model shipped in the package can run; downloading models from the internet is switched off in code, so changing the model requires a new version reviewed by IT.
  • Storage: settings in storage.local; the placeholder-to-value map in storage.session only (memory, cleared when the browser closes).
  • Runs on: chatgpt.com, claude.ai, gemini.google.com, copilot.microsoft.com, perplexity.ai, chat.deepseek.com, chat.mistral.ai, grok.com, poe.com. Users can add other sites, which asks for permission per site.
  • Permissions: storage, contextMenus, scripting, activeTab, offscreen (runs the model), declarativeNetRequest (only used for the optional local engine). Host access is limited to localhost / 127.0.0.1.
  • Optional engine: a power user can switch detection to a local Ollama server on the same machine. If someone enters a server that is not on their computer, the settings page shows a warning that text will be sent there.
  • Third-party code: Transformers.js and ONNX Runtime Web (run the model), fflate (Office files), and the DistilBERT-NER model (English, 66 MB). All open source. Only vendor/ holds these; everything in src/ is readable source written for this tool.
  • Testing: 272 unit tests, 91 automated browser tests with the real extension, and a 3,501-case stress test of MENA names, phones and IDs.

Option 1: quick test on one machine

  1. Unzip local-ai-anonymizer-{{VERSION}}.zip to a permanent folder.
  2. Open chrome://extensions or edge://extensions, turn on Developer mode.
  3. Click Load unpacked and select the folder (the one containing manifest.json).

Fine for a pilot. No automatic updates, and Developer mode may be blocked by your policies.

Option 2: deploy to managed devices (recommended)

  1. Sign it. Unzip, then run Chrome with --pack-extension="<folder>". This creates <folder>.crx and a private key <folder>.pem. Keep the key safe: every future version must be signed with it, and it fixes the extension ID.
  2. Get the ID. Drag the .crx onto chrome://extensions on a test machine with Developer mode on; the ID is shown on the card.
  3. Host two files on an internal HTTPS location the devices can reach: the .crx and this update.xml: 
    <?xml version='1.0' encoding='UTF-8'?>
<gupdate xmlns='http://www.google.com/update2/response' protocol='2.0'>
  <app appid='EXTENSION_ID'>
    <updatecheck codebase='https://YOUR-HOST/anonymizer/local-ai-anonymizer.crx' version='{{VERSION}}' />
  </app>
</gupdate>
  4. Set the policy ExtensionInstallForcelist (same name in Chrome and Edge; in Intune Settings catalog under Google Chrome > Extensions and Microsoft Edge > Extensions) to: 
    EXTENSION_ID;https://YOUR-HOST/anonymizer/update.xml
    If you use an extension allowlist, add the ID to ExtensionInstallAllowlist too.

Browsers accept self-hosted extensions only on managed devices (domain-joined, Intune/MDM-enrolled, or Chrome Enterprise enrolled). Staff see the guide open once after install.

Updates

For a new version: unzip it, pack it with the same .pem key (--pack-extension="<folder>" --pack-extension-key="<key>.pem"), replace the .crx, and raise version in update.xml. Browsers update within a few hours.

Known limits (also in the staff guide)

  • Detection catches most personal data, not all. Staff should still glance at text before sending.
  • Names written in Arabic script are not detected yet (Arabic labels for phones and IDs are).
  • Uploads of PDFs and images are held, not cleaned; the user decides.
